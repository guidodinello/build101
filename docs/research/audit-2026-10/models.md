# Model selection

This doc covers which AI model each Neitor AI agent should run on (the orchestrator, post drafter, Brand Strategist, Asset Analyst, Conversation summarizer, Niche Analyst, scene images and voice transcription), compared on price, quality, latency and migration risk. It is one dimension of the product and codebase audit of 2026-10-19 (index in [README.md](README.md), cross-dimension synthesis in [summary.md](summary.md)); the code was read at commit `dc0bc01`. An independent adversarial reviewer checked each finding against the code and the cited sources; "adjusted" means the reviewer corrected its severity or details, and the severity and recommendation below already include those corrections. In code link text, files under `backend/app/` drop that prefix, tests show `tests/...` (under `backend/`), and migrations show only the file name; every link points at the full path. Amounts are US dollars ($). Cost figures are estimates until per-call metering in `agent_runs` exists (MOD-3; COST-1 in [unit-economics.md](unit-economics.md)).

## Summary

- **Today.** Every text agent (orchestrator, post drafter, Brand Strategist, Asset Analyst, Conversation summarizer and Niche Analyst) runs on one model, gemini-3.8-flash ([config.py:40](../../../backend/app/config.py)), with only the thinking level changing per agent ([ADR 0023](../../decisions/0023-gemini-text-llm.md)). Scenes use gemini-nano-banana-2.1 at 2K with medium thinking ([config.py:28-30](../../../backend/app/config.py)). Voice notes depend only on Kapso's transcript, because the Gemini fallback was never built ([conversation/chat.py:178-191](../../../backend/app/conversation/chat.py)).
- **Images: keep Gemini.** Nano Banana 2.1 is the cheapest model that takes 10 product references and fits the 4:5 format, so the work there is spending less per post (1K for framed slides, minimal thinking, no new AI scenes when only the slide text changes), not changing provider (MOD-6, MOD-7, MOD-8, MOD-15).
- **Text: the picture changed after the ADRs were written.** Gemini 3.8 Flash doubles in price on 2027-01-01, right as pilots start. Claude Haiku 5.5 (released 2026-10-07) and GPT-6 Luna cost $0.10/$0.50 per 1M tokens, 7.5x less than Flash today and 15x less from January. Their headline Artificial Analysis scores (43 and 38, against 41 for Flash at high) are Max-effort variants with 272 s and 99 s to the first token; at a usable effort, Haiku needs high (38) or xhigh (41) to match Flash at medium (40), and Luna never reaches Flash (MOD-1). A cheap tier for the orchestrator is still the biggest saving available, about 75-85% of orchestrator text cost now and 85-90% after January at Haiku high or xhigh, but only if an eval passes at that effort level.
- **The code is half ready.** Every call already goes through the `ChatModel` port with an `agent` name, so routing each agent to its own model is cheap (MOD-2). But there is one global model setting, the stored history and the tool schemas use Gemini's own format (MOD-11), the live evals are hardcoded to `GeminiChat` (MOD-4), and nothing records cost or cache hits: `agent_runs` is never written (MOD-3).
- **Order of work, before the January price change:** telemetry (MOD-3), per-agent routing (MOD-2), a model-neutral eval on Rioplatense Spanish (MOD-4), then the switch (MOD-1).

## Findings

### MOD-3: Record cost and cache telemetry per call: `agent_runs` exists but nothing writes it, and image usage is dropped on success

- **Severity**: high · **Effort**: S · **Confidence**: high · **Verified**: confirmed
- **Evidence**: [0001_initial.sql:301-316](../../../backend/migrations/versions/0001_initial.sql) (`agent_runs` with model, effort, input_tokens, output_tokens, cache_read_tokens and latency_ms; no code writes it, and nothing in `backend/app` references it); [llm/client.py:246-255](../../../backend/app/llm/client.py) (logs input, output and thought tokens but not `usage.total_cached_tokens`, which the SDK exposes in `google/genai/_gaos/types/interactions/usage.py`); [carousel/generator.py:186-191](../../../backend/app/carousel/generator.py) (image usage is logged only when a carousel fails; the success path in [posts/maker.py:325-338](../../../backend/app/posts/maker.py) drops it); [ADR 0019:28](../../decisions/0019-image-provider-gemini.md) ("log the response usage ... with every call"); [ADR 0021:33](../../decisions/0021-voice-notes-kapso-transcript-gemini-fallback.md) (transcriptions logged to `agent_runs`); [open-questions.md:58](../../open-questions.md) (the real cost per carousel is still unmeasured); [Gemini caching](https://ai.google.dev/gemini-api/docs/caching) (implicit caching works in stateless Interactions mode, minimum 4,096 tokens on 3.8 Flash, hits reported in `usage.total_cached_tokens`; read 2026-10-19).
- **Problem**: The team can't answer "what does an Owner cost us?" or "is implicit caching hitting?" (the prompt layout in `context.py` was designed for caching but is never checked). Without that, no model A/B and no pricing in [ADR 0031](../../decisions/0031-pricing-free-basic-pro.md) can be judged on numbers. Thought tokens, billed at the output rate (5x input on Flash), are logged but never totalled per agent.
- **Recommendation**: In `GeminiChat._create` (and `GeminiImageGen.generate`), write one `agent_runs` row per call: agent, model, thinking level, `service_tier`, input, cached, thought and output tokens, `latency_ms`, error, and the estimated cost from a small price table in code (dated, with the 2027-01-01 Flash prices). Pass `business_id` and `job_id` through a contextvar to avoid changing signatures. Add `total_cached_tokens` to the log line. Add a SQL view of cost per Business per day and per agent. Store `GeneratedSlide.usage` for successful posts too. The table needs a small migration for thought tokens and `service_tier` (verifier).
- **Impact**: Turns every later finding (MOD-1, 6, 7, 8, 12) into a measurable decision, gives the real cost per Owner for the Free tier cap (ADR 0031), and catches a broken cache prefix early (one could silently double orchestrator cost).
- **Verifier note**: Checked and true. Nothing in `backend/app` or `backend/tests` references `agent_runs`, although the table exists. T10's done-when in [tasks.md:39-40](../../implementation/tasks.md) explicitly requires "an agent_runs row exists", so this is an unmet commitment of T10; ADR 0019:28 and ADR 0021:33 also promise usage logging. Google's caching docs confirm implicit caching in stateless mode, the 4,096-token minimum on 3.8 Flash and hits in `usage.total_cached_tokens`. `GeminiImageGen` collects usage ([imagegen/gemini.py:130-149](../../../backend/app/imagegen/gemini.py)), but the success path in [posts/maker.py:319-338](../../../backend/app/posts/maker.py) discards the `GeneratedSlide.usage` values; only `gather_slides` logs them, and only when the carousel fails ([carousel/generator.py:178-195](../../../backend/app/carousel/generator.py)). Small notes: `agent_runs` has no thought_tokens or service_tier column, so a small migration is needed, and orchestrator turns are keyed by phone number, so `business_id` needs a lookup. Neither changes the S effort. High is justified: this is the prerequisite for every cost decision, and for ADR 0031's Free-tier economics during the pilot.

### MOD-1: Move the orchestrator (and small agents) to a cheap tier before Gemini 3.8 Flash doubles in price on 2027-01-01

- **Severity**: medium · **Effort**: L · **Confidence**: medium · **Verified**: adjusted
- **Evidence**: [config.py:40](../../../backend/app/config.py) (`gemini_chat_model = "gemini-3.8-flash"` for every text agent); [conversation/chat.py:417-420](../../../backend/app/conversation/chat.py) (up to `MAX_STEPS=5` model calls per turn, each resending the full history); [conversation/history.py:22](../../../backend/app/conversation/history.py) (`MAX_HISTORY_TOKENS = 40_000` resent on every call); [ADR 0023:12](../../decisions/0023-gemini-text-llm.md) (one model for all agents; only the thinking level varies); [agents.md:27](../../architecture/agents.md) ("gemini-3.8-flash for every agent... rather than switching models"); [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing) (3.8 Flash $0.75 in / $3.75 out, rising to $1.50 / $7.50 on 2027-01-01; cache $0.075 rising to $0.15; read 2026-10-19); [Haiku 5.5 overview](https://platform.claude.com/docs/en/models/haiku-5-5/overview) (released 2026-10-07, $0.10 in / $0.50 out for prompts up to 100k, cache read $0.01, 1M context, vision, adaptive thinking; read 2026-10-19); [Artificial Analysis, Claude Haiku 5.5](https://artificialanalysis.ai/models/claude-haiku-5-5) (Intelligence Index 43, 232 tok/s, blended $0.08; read 2026-10-19); [Artificial Analysis, Gemini 3.8 Flash](https://artificialanalysis.ai/models/gemini-3-8-flash) (Intelligence Index 41 at High, 150 tok/s, TTFT 24.4 s, blended $0.58; read 2026-10-19); [GPT-6 Luna model page](https://developers.openai.com/api/docs/models/gpt-6-luna) ($0.10 / $0.50, effort none to max, function calling and structured outputs) and [Artificial Analysis, GPT-6 Luna](https://artificialanalysis.ai/models/gpt-6-luna) (Intelligence Index 38) (both read 2026-10-19).
- **Problem**: Text costs are about to double for every agent. The orchestrator is the largest text cost: each WhatsApp turn is 1-5 calls, each resending a system prompt of about 7k tokens plus up to 40k tokens of history. The auditor estimates about $0.010-0.019 per call today and $0.021-0.039 from January (cache hit rate unknown, see MOD-3). For a Basic Owner (3 posts a week, 150-300 orchestrator calls a month) that is about $1.6-5.7 a month now and $3.1-11.4 from January, on a $29 plan. Two vendors now sell models priced like Flash-Lite whose headline Artificial Analysis scores are at or above Gemini 3.8 Flash; verification found those are Max-effort scores (see the verifier note). Gemini's own cheap option is worse: 3.5 Flash-Lite scores 22 and costs more than Haiku 5.5 (MOD-14).
- **Recommendation**: Keep the eval-first approach, but compare at matched intelligence. Use gemini-3.8-flash at medium (current Owner turns) and at low (event turns) as the baseline. Test claude-haiku-5-5 at medium, high and xhigh (Artificial Analysis: high 38, xhigh 41, versus Flash medium 40). Test gpt-6-luna only at medium or high (29/32), or drop it. Score tool-call correctness, Rioplatense tone, p95 latency per turn and cost per turn using MOD-3 telemetry. Measure Gemini's implicit-cache hit rate before estimating savings. Switch only if Haiku matches at an effort level that keeps p95 latency under the 20 s keep-alive. Keep prompts under 100k Haiku tokens, where the higher price tier starts. Record the result in an ADR that supersedes ADR 0023 for the orchestrator only (needs an ADR; ADR 0023 is "proposed" and was written 2026-10-17).
- **Impact**: The auditor estimated orchestrator text cost drops about 80-90% now and 90-95% after 2027-01-01: about $1.3-5 saved per Basic Owner a month today and $3-11 from January, which protects the margin assumed in [roadmap.md:50](../../roadmap.md). ### MOD-11: Stored history and tool schemas use Gemini's Interactions format, so a second provider needs a translation layer

- **Severity**: low · **Effort**: M · **Confidence**: high · **Verified**: adjusted
- **Evidence**: [llm/client.py:21](../../../backend/app/llm/client.py) (`Step` is a raw Interactions API step dict); [llm/client.py:127-131](../../../backend/app/llm/client.py) (thought steps carrying Gemini signatures must be stored and resent unchanged); [conversation/factory.py:57](../../../backend/app/conversation/factory.py) (`DbHistory` persists those steps in Postgres); [conversation/tools.py:5-70](../../../backend/app/conversation/tools.py) (tools in Gemini's `{'type': 'function', 'parameters': ...}` shape, with minimum and maximum); [Haiku 5.5 overview](https://platform.claude.com/docs/en/models/haiku-5-5/overview) (Haiku 5.5 thinking blocks work only in the account that produced them; read 2026-10-19); [Claude structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs) (strict schemas don't support minimum and maximum; read 2026-10-19).
- **Problem**: Every stored conversation contains Gemini-only thought signatures and Interactions-shaped steps, so moving the orchestrator to Claude or OpenAI, and later back, cannot simply replay the stored history. The auditor framed this as a data migration in both directions; verification found an on-the-fly translation is enough (see the verifier note). An A/B or a fallback on live conversations is risky without that translation layer.
- **Recommendation**: When, and only when, a Claude or OpenAI adapter is built, translate the stored Interactions steps per request inside the adapter: drop foreign thought steps, and map `function_call` / `function_result` to `tool_use` / `tool_result`. Leave the storage format alone, and at cutover optionally run the Compactor so little raw history crosses providers. Generate the Claude tool schemas from the existing tool dicts or pydantic args and keep validating in code. No neutral turn model is needed up front.
- **Impact**: Makes MOD-1 and MOD-10 safe to do on live data, and the same cutover works for any future model change.
- **Verifier note**: The format coupling is real: `Step` is a raw Interactions dict, thought steps with signatures are stored and resent (`DbHistory`), and the tools use Gemini's function shape with minimum and maximum. Claude's strict mode rejects minimum and maximum with a 400, but the SDK helpers strip them into the description, and non-strict tool use accepts them. Haiku 5.5's thinking blocks are account-bound. But "switching provider means migrating data" and "switching back fails the same way" were overstated. The stored steps are already structured (`user_input`, `model_output`, `function_call` with id, name and arguments, `function_result` with call_id, name and result), and `transcript()` in [conversation/history.py:236-260](../../../backend/app/conversation/history.py) already renders them provider-neutrally for the summarizer. A Claude adapter can translate them on the fly and drop Gemini thought steps, with no data migration. Gemini validates thought signatures only for the current turn, and documents a `skip_thought_signature_validator` value for foreign function calls, so switching back also works. This is a small part of building a second adapter, not a separate medium-severity debt.
- **Related**: MOD-1, MOD-13 (this doc)
